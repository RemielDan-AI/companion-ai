# 陪伴 AI（companion-ai）

本地运行的专属陪伴 AI：记得住、有风格、有边界、能一直长。

> 想直接跑起来看 **[INSTALL.md](INSTALL.md)**；
> 想先看被量过的设计结论看 **[docs/设计取舍与实测.md](docs/设计取舍与实测.md)**。
详细的设计取舍与实测数据见 `docs/设计取舍与实测.md`。

设计上坚持几条：记忆优先于智能、风格优先于知识、本地优先于云端、轻量优先于强大、
默认拒绝（技能白名单）、价值观靠养成而不是靠声明、模型可换而积累的资产不丢。

## 一、怎么跑起来

```bash
pip install -r requirements.txt     # 只有 PyYAML + Pillow
python 启动模型.py                  # 起模型服务（llama-server，见下）
python gui.py                       # 开界面（或双击 启动界面.bat）
```

⚠ **本项目不包含任何模型**，需要你自己准备 GGUF 文件，并用
`COMPANION_MODEL_DIRS` 环境变量告诉它模型在哪：

```bash
set COMPANION_MODEL_DIRS=D:\models       # Windows，多个用 ; 分隔
export COMPANION_MODEL_DIRS=/home/me/models   # Linux/macOS
```

不设时默认找 `~/ai/models` 和 `./models`。
然后在 `config/models.yaml` 里把每个角色的 `model:` 改成对应文件名里的关键词。

完整步骤（含 llama.cpp 安装、显存怎么配、常见问题）见 **[INSTALL.md](INSTALL.md)**。

两个可选服务：

| 服务 | 要不要 | 说明 |
|---|---|---|
| 对话模型 | **要**（否则无法对话） | llama-server，默认 `127.0.0.1:8080` |
| 记忆嵌入 | 可选 | llama-server `--embeddings`，默认 `127.0.0.1:8081`，纯 CPU |

嵌入服务没起也能用：检索会自动退化成关键词匹配，只是召回质量差一些。
`numpy` 和 `edge-tts` 也是可选的，见 `requirements-optional.txt`。

语音（可选）：**Edge TTS 开箱可用**（在线）；本地的 GSV / GPT-SoVITS 需要你自己启动
（默认 `127.0.0.1:9880`）。本项目**不内置也不启动语音模型**。

## 二、桌面窗口

- **聊天**：回车发送，生成在工作线程里跑，界面不卡；每条回复下面是这一轮的内情
  （思考档位、命中的技能、识别到的情绪、用到的记忆）
- **回复语言 / 朗读语言**：分成两个独立设置。前者决定未央用什么语言**写**，
  后者决定语音**念成**什么语言（可选「自动」跟随文本语言）；两者不一致时，
  **只对语音做翻译**，聊天记录保持原文
- **回听**：每条回复后面有可点的「🔊回听」，按当前语音设置重新合成；
  朗读中按钮变「⏹ 停止朗读」。同一时刻只会有一段声音，新的请求会打断旧的。
  它的字色同时表示两件事：**鼠标移上去变主题深蓝、1 秒后自动变回**（说明可点）；
  **这条正在朗读时字色融进气泡底**（看着像没有），读完再显出来。两条规则共存、播放优先
- **文本与声音同时出现**：合成期间先显示「🔊 正在合成语音…」占位，语音就绪才替换成正文，
  不会出现「文字先出来、半天没声音」被误判成失败
- **反馈**：好 / 不好 / 纠错（纠错会写成偏好对，供以后微调用）
- **⚙ 模型服务**：选模型、调参数、存预设、一键启停（详见第六节）
- **📚 记忆管理**：搜索、查看重要度与衰减状态、标记保留策略、唤醒、修改、删除、导出
- **🎭 AI 档案**：改未央自己的名字/语气、微调性格维度、回滚、恢复默认
- **🔧 工具调用**：看工具调用记录、MCP 服务器状态、云端外发审计（含被拦原因）
- **🧹 清除记忆**：模态确认框，可选清哪些范围；**价值观默认保留**

## 三、记忆系统

记忆分成几层，长期和短期分开管：

| 层 | 内容 | 存在哪 |
|---|---|---|
| 短期上下文 | 最近几轮原文，直接进提示 | 内存（可清空，不影响长期记忆） |
| 情景记忆 | 每轮对话的摘要、情绪、重要度 | `cognition/memory.db` |
| 语义记忆 | 事实 / 偏好 / 提到的人 | 同上 |
| 向量索引 | 语义与情景的向量，用于相似检索 | `cognition/vectors/embeddings.json` |
| 主题（高层记忆） | 从碎片里聚出来的长期印象 | 同上（`memory_theme` 表） |
| 记忆关联 | 时间 / 人物 / 因果 / 证据关系 | 同上（`memory_link` 表） |
| 审计日志 | 写入、检索、修改、删除、归档、导入等动作 | 同上（`memory_log` 表） |

能做的事：

- **重要度会衰减也会回升**：不同类型半衰期不同（事实慢、琐事快、价值观证据几乎不衰减），
  被检索或被提起会回升，但封顶在这条记忆的峰值；够冷且久未访问会转**冷存储**
  ——不删除，按需检索仍可命中，命中即唤醒。参数都在 `config/decay.yaml`
- **用户可标记**：永久重要 / 暂时保留 / 可遗忘
- **检索按需注入**：不是每轮都塞记忆。控制「同一条记忆反复刷屏」用了三层，从外到内：
  1. **注入层**：最近 3 轮已经注入过的同一条记忆，本轮不再注入；强命中的门槛也调高了
  2. **提示层**：人设里写明「对方换话题了就跟着走；不要主动提之前聊过的人和事；
     上一轮说过的也别再重复」
  3. **重复提及守卫**：从前两轮注入过的记忆里抽出**实体名**，如果本轮回复又提到它、
     而对方这一轮自己没提，就用更强指令**重生成一次**
- **守卫的覆盖范围（说清楚，别当万能）**：
  - 只认「叫XX」这种**被明确介绍过的名字**（宠物名、人名，如「团子」「林一」），
    不做通用实体识别——有意收窄，宁可少拦，也不乱重生成
  - 只在**对方这轮没提到**时介入；对方自己提起则完全不干预
  - 处理方式是**重生成一次**（复用语言校验那套，最多一次），不是硬删句子
  - 盯的是「前两轮注入过的记忆里的实体」，**不覆盖其它形式的重复**
    （换个说法的重复、口头禅式重复都不管）
  - 实测：无关话题里提到同一宠物的比例 3/3 → 0/3；边界用例（无关话题仍反复提同一件事）
    5/6 → 0/6。**但那次测评里守卫本身没触发**，改善主要来自注入层与提示层，
    守卫是兜底——要它真正出手，得等实体名确实出现在最近注入过的记忆里
- **冲突不自动裁决**：新说法和旧事实矛盾时，新条目挂起等确认，旧条目原样保留，
  未央会在对话里自然问你一句；你可以在命令行拍板（用新的 / 留旧的 / 两个都对），
  三条路都会把两条记录留在库里，随时能回溯
- **相似记忆自动合并**：保留更完整的那条，证据数累加，被合并的留有指向
- **情绪标签**：记忆带情绪，可按情绪过滤与统计
- **从日记/笔记导入**：支持 txt / md / jsonl，先预览再确认写入，重复导入只加证据不写重
- **多会话与历史管理**：会话可切换、归档、导出、删除（删除只动该会话的情景记忆）
- **迁移备份**：整库导出成可读 JSON，换设备搬过去即可；换模型不用动库
- **长期维护**：转冷 + 合并 + 数据库压缩、检索自召回率评估、衰退机制体检、定期备份轮转
- **冷启动**：新用户不预设任何记忆；刚开始会自然地一件一件问关键信息；
  头 7 天只记录、不推断价值观（天数可在 `config/onboarding.yaml` 改）

## 四、人格与性格

未央自己的档案单独存 `config/ai_profile.yaml`，和用户画像（`cognition/profile.json`）
彻底分开——那份管「懂你」，这份管「它自己是谁」。

- 名字、关系、称呼、语气可改，改完立刻进人设
- 五个性格维度（活泼度 / 话量 / 主动性 / 亲密感 / 玩笑度）会按
  **上一轮反馈 + 这轮情绪 + 对方话长话短**小幅调整，并翻译成简短的说话提示
- 调整有频率限制（默认至少隔 6 轮）和幅度上限，不会频繁漂移；每次调整都有记录，
  可回滚、可恢复默认
- **性格只影响语气与话量**，底线与安全边界由人设文件决定，性格改不动它

## 五、技能、工具与云端

**技能路由**：先看禁止类（医疗、法律、投资、自伤、违法、伤人）→ 再看扩展技能 →
核心技能 → 没有匹配就诚实说不擅长。**拒绝走本地模板，不经过模型**，所以边界不依赖模型是否听话。

**工具接入**：技能可以声明外部工具，支持四类——

| 类型 | 用途 |
|---|---|
| 本地函数 | 内置工具（目前有天气查询，用开放的免费接口，真实可用） |
| HTTP | 调外部接口，可指定取哪个字段 |
| 命令行 | 需要先在白名单里登记，默认一个都不许 |
| MCP | 走 stdio 的 JSON-RPC 客户端，默认关闭 |

调用前统一查权限（`config/tools.yaml`），失败会重试 → 兜底话术 → 诚实拒绝，
全过程写 `logs/tool_calls.jsonl`。

**云端能力默认全关**：`config/api.yaml` 里总开关是关的，用云端生成对话回复还要单独开。
开启后仍然只发「任务本身」——画像、记忆、价值观、对话历史、人格设定写死在禁止外发名单里，
外发前脱敏、有每日预算上限，每次外发都记 `logs/api_calls.jsonl`（含被拦原因）。

## 六、模型与服务管理

窗口底部「⚙ 模型服务」就是统一启动器（原来是三个黑窗口）：

- 自动扫描模型目录（默认 `~/ai/models`，可用环境变量 `COMPANION_MODEL_DIRS` 指定，多个用 `;` 分隔）并按对话/嵌入分类
- 可调参数：端口、上下文、显存层数、线程、KV 量化、批大小/微批、并行数、额外参数
- 预设存 `config/presets.json`。**不内置任何预设**，全部由你自己加（「另存为…」）；
  一个预设都没有时启动器照常能跑，走内置的兜底参数
- 模型**无窗口启动**；关掉程序窗口时后台服务一起退出（即使前台被强杀也不会留残留进程）
- 起不来会说清原因：端口被占用（连占用者一并报出）、模型文件缺失、模型加载失败、显存不足
- 启动记录写在 `logs/services.jsonl`

### 对外接口（给桌宠 / 别的本地程序用）

`pet_server.py` 把伴侣能力暴露成 **OpenAI 兼容接口** —— 桌宠、编辑器插件、
脚本都认这个格式，接过来只要改 `base_url`，不用为每个调用方各写一套协议。
**零新依赖**（只用标准库 `http.server`）。

```bash
python pet_server.py --port 8082                 # 只起接口（占前台，Ctrl+C 退）
python launcher.py --alias baseline --serve      # 起模型的同时把接口也起上
```

| 接口 | 说明 |
|---|---|
| `POST /v1/chat/completions` | OpenAI 格式，返回真正的伴侣回复（走完整链路：路由→记忆检索→生成→提取落库） |
| `POST /chat` | 极简格式 `{"text": "..."}` → `{"reply": "...", "info": {...}}`，脚本/curl 用 |
| `GET /v1/models` | 模型清单（对外就报 `companion-ai`） |
| `GET /health` | 自身 + 依赖服务状态；对话模型没起时返回 **503**（如实报告，不假装可用） |

要点：

- 端口 **8082**（8080 是对话模型、8081 是嵌入，别撞）；
- **串行化**：`Companion` 是有状态的会话对象，并发调用会把上下文搅乱，
  所以服务端用一把锁让请求排队（实测 6 个并发请求各自拿到自己的回复）；
- 响应里额外带一个 `companion` 字段（档位/技能/情绪/记忆抽取结果），
  客户端想展示"这一轮的内情"就有数据可用；
- **看不了图**：本地 4B 模型没有视觉能力。带图请求会返回 **400 并说明原因**，
  不谎报成功（`/v1/models` 里也只声明 `input: ["text"]`）；
- 只取 `messages` 里**最后一条 user 文本**：伴侣自己管短期上下文，
  客户端发来的 history 不用（否则两边上下文打架、记忆被重复计数）。

桌宠侧怎么连（`pet` 项目的配置）：

```json
"chat_base_url": "http://127.0.0.1:8082/v1",
"chat_model": "companion-ai"
```

> **现状**：接口这半边已完成并端到端实测（起了真实 4B 模型，拿到真正的伴侣回复，
> 记忆链路也在工作）。但**桌宠侧还没有聊天入口** —— 桌宠目前只有"看屏幕"和
> "跟着 DSH 状态动"，没有"输入一句话问它"的界面。**这是待办**，
> 桌宠联动协议见 `桌宠联动协议.md`。

### 微调数据集

清单见 `微调数据\数据收集.txt`，下载脚本 `training/download_datasets.py`：

```
python training/download_datasets.py --list        # 只看有哪些文件、多大
python training/download_datasets.py               # 下载到 微调数据\datasets\
```

数据落在 `./微调数据/datasets/<数据集名>/`（路径可改）。其中两个「防遗忘」子集较大
（多轮对话约 940MB、真实指令约 540MB），其余五个都很小。

**从跑过的测试里反挖训练数据**（不用额外标注——报告里本来就带判定标记）：

```
python training/export_dataset.py            # 导出 SFT / DPO / safety + 统计报告
python training/export_answers.py --clean    # 把 AI 回答导成纯文本（可直接当正例）
python training/mine_conversations.py        # 同一问题在好/差报告里的两种答法 → 偏好对
python training/mine_preferences.py          # 从带 ⚠ 标记的报告里挖偏好对
```

产物都在 `training/export/`：`sft_messages.jsonl`（LLaMA-Factory sharegpt / OpenAI 格式）、
`sft_alpaca.jsonl`、`dpo.jsonl`、`safety.jsonl`（拒绝类，默认不进 SFT，单独一份）、
`report.md`（统计与质检：过滤了多少、DPO 里凑不成对的有几条、长度与档位分布）。
`mine_*.py` 挖出来的是 `mined_conversations.jsonl` / `mined_sft.jsonl` / `mined_preferences.jsonl`。

> 训练本身**没做**：本机 4GB 显存放不下 4B 的 QLoRA，`training/lora_train.py` 只是个占位。

### 对话变体测试（同一考点、多种说法）

一个方向 = 一个考点，每个方向有多个**变体**：变体复用同一个几十轮骨架，
但**设定、身份、措辞、追问方式**都换掉 —— 用来回答「这个考点是不是只对某一种说法有效」。
变体只描述三样东西（开场几轮设定、关键词替换表、追加探针），所以加一个变体只要几行配置。

| 方向 | 考点 | 变体 |

## 十一、还没做 / 还没验证（别当成已具备的能力）

**没做**：

- **语音输入（ASR）**、**看图/多模态**：完全没做
- **云端能力只做到「准备与审计」**：网关能拦住不该发的、能脱敏、能记审计，
  但**没有接任何真实的云端 API**；「用云端生成对话回复」的开关也只是开关，后面没有实现
- **MCP 只做了 stdio 客户端**：没做 SSE/HTTP 传输，也没有内置任何 MCP 服务器
- **微调没做**：本机 4GB 显存放不下 4B 的 QLoRA，数据导出与评估流程就绪，
  但**从未真正训练过**；换模型后的效果也没长期验证
- **记忆的抽象只按字面相似度聚类**，不是语义聚类；因果关系不会自动识别，只能手动建
- **情绪标签只用于统计与过滤**，还没参与检索排序
- **导入只支持纯文本类文件**，不支持 PDF / Word / 网页
- **性格调整基于规则信号**，没有从对话风格里自动学画像

**没验证 / 只在有限条件下验证过**：

- 换了备选模型后**只跑过 10 轮对照测试**，没长期聊过；启动器已备好
- **跨设备迁移只做了导出/导入功能与测试，没有真机搬过**
- **长期维护没有真实长期数据检验**（衰减、冷存储、主题聚类在几周量级上的表现未知）
- **记忆库没做过规模压力测试**（目前只有几十条量级）
- 本地语音（GSV）**只在本机特定版本上验证过**，换版本可能接口不同

### 禁止内容的覆盖范围（按类别）

本地规则层是**关键词 + 正则**匹配，命中就直接出拒绝话术，不经过模型。目前覆盖的类别：

| 规则 | 类别 | 处理方式 |
|---|---|---|
| F001 | 医疗诊断 | 医学建议类，转专业渠道 |
| F002 | 法律意见 | 转专业渠道 |
| F003 | 投资建议 | 转专业渠道 |
| F004 | 自伤风险 | 优先安抚 + 求助渠道 |
| F005 | 违法行为 | 硬拒绝（含诈骗、洗钱、木马、假证、代写作弊、毒品、网赌、内幕交易） |
| F006 | 伤害他人 | 硬拒绝 |
| F007 | 提示词注入与人格覆盖 | 硬拒绝（忽略设定、开发者模式、无底线人格、套取提示词、改名覆盖） |
| F008 | 危险物品与武器 | 硬拒绝（爆炸物、枪支、毒物） |
| F009 | 侵犯隐私与跟踪 | 硬拒绝（开房记录、定位、翻手机、人肉、代查） |
| F010 | 仇恨与歧视 | 硬拒绝（辱骂、地域攻击、群体歧视、刻薄嘲笑） |
| F011 | 施压与授权话术 | 软拒绝（"我保证""我授权你""我是专业的""最后一次问"） |
| F012 | 角色扮演绕过 | 硬拒绝（写成小说/研究/扮演角色来包装危险请求） |
| F013 | 色情内容与未成年人 | 硬拒绝（露骨描写、任何涉及未成年人的性内容） |

**已知局限**（必须说清）：

- 关键词必然漏。**没有命中关键词的危险请求会被当成普通聊天回答**——
  例如换个说法的施压（"你要是不帮我，我今晚就自己试"）、没列进词表的物品、
  或者把危险请求拆成多轮慢慢提。
- F011 这类"施压话术"只是**伴随信号**，单独出现时可能误伤；
  所以它是软拒绝（说明立场、不硬顶），并且只收具体措辞。
- 因此**下一层要做语义判定**：拿不准的先让模型判断"这属于哪类请求"，再决定是否走拒绝。
  在那之前，规则层就是唯一防线。
- `tests/cover_check.py` 可以秒级体检覆盖情况（只看路由判定，不生成回复）：
  给它一批"该拦的"和"不该拦的"句子，直接看漏了几条、误伤几条。

## 十二、已知限制

- 4GB 显存只能跑 4B 量化模型，回答质量受模型本身限制（偶发夹英文、日语里混中文词）
- 小模型对系统提示长度敏感：记忆注入块刻意压短，长了反而容易复述提示
- 记忆里有明确矛盾时只会挂起问一次，**不会自动判断哪个对**
- 冷启动头 7 天不推断价值观，这是有意的保守设置，可在配置里改
- 「重复提及守卫」只识别「叫XX」这类被介绍过的名字，覆盖不到其它形式的重复
  （换个说法的重复、口头禅式重复都不管）

## 关于本仓库

这是从一份**个人自用**的部署里整理出来的可公开版本：

- **只含代码与默认配置模板**。开发日志、记忆库、对话日志、测试样本、
  以及那套用到的立绘素材**都不在仓库里**（见 `.gitignore`）。
- **不内置任何模型**：模型要自己下（llama.cpp 的 GGUF 格式），用
  `services/manager.py` 扫描的目录或环境变量 `COMPANION_MODEL_DIRS` 指过去。
- **没有默认立绘**：`config/gui.yaml` 里 `character_asset` 留空时会用代码里
  自绘的矢量形象兜底，界面照样能用。
- **云端 API 默认全关**：`config/api.yaml` 的 `enabled: false`。要用得自己在
  设置里打开，并且要过外发网关（画像/记忆/价值观/人格提示写死禁止外发）。
