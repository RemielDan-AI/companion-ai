# 设计取舍与实测

这份文档只记录**被量过**的结论。每条都写了「怎么测的」和「不适用什么」——
没测过的设计选择不写在这里（那些属于个人口味，不该冒充结论）。

---

## 1. 本地闭端口 `connect` 会挂满整个超时，不是立刻 `ECONNREFUSED`

`socket.connect(('127.0.0.1', 8099))` 在 Windows 上实测 **1503 ms** 才失败。

这违反直觉（一般人以为本机端口没开就立刻返回），后果很直接：
**界面上任何「同步探活」都会卡住整个 Tk 主循环**。设置窗口当初打开要
7.7 秒，就是被几次探活累加出来的。

做法：
- 探活超时压到 **0.35 s**，并加 **0.5 s TTL 缓存**（一次面板构建会问十几次）
- 多个端口用线程池并发探
- 一律不放在主线程

结果：设置窗口打开 **7.7 s → 0.32~0.47 s**。

> 不适用：只在 Windows 上测过。Linux 上闭端口通常立刻 `ECONNREFUSED`，
> 那套超时逻辑仍然正确，只是不会触发。

## 2. 4 GB 显存下，五个服务同时在线是**放不下**的

RTX 3050（4096 MiB）、15.19 GB 内存。逐个启动后量系统可用内存：

| 累积启动 | 可用内存 |
|---|---|
| 基线 | 7.25 GB |
| + 对话模型（v1.5，ngl=20） | 4.83 GB |
| + 嵌入（bge-small，CPU） | 4.71 GB |
| + 记忆抽取（Qwen3.5-2B，ngl=12） | 3.30 GB |
| + 判官（Qwen3-4B，ngl=0） | 1.22 GB |
| + 思考模型（Qwen3.5-9B，ngl=20） | **0.03 GB** ← 不可用 |

五个全上 = RSS 合计 9.33 GB，**只剩 30 MB**，系统会开始换页。

所以「思考模型」默认**不常驻**，按需起停；并且和判官**互斥**（起 9B 前先关 4B）。

---

## 3. 判官召回率：2B 50% / 4B 83% / 9B 100%

12 条**程序侧判不了**的困难编造样本（程序侧 0/6 命中），让三个模型当判官：

| 模型 | 召回 | 单条耗时 |
|---|---|---|
| Qwen3.5-2B | 50% | — |
| Qwen3-4B | 83% | — |
| Qwen3.5-9B | **100%** | 1.3 s |

所以判官候选是 `[think, judge]`（9B 在就用 9B），**2B 被写死禁止当判官**。

> 不适用：样本只有 12 条，且都是"程序判不了"的难例；
> 换成普通编造样本，2B 未必这么差。

---

## 4. `ngl` 不是越大越好：2B 记忆模型在 ngl=12 最好

同一个 Qwen3.5-2B，只改 GPU 层数（其余不变）：

- `ngl=0`（纯 CPU）比 `ngl=12` **慢 5 倍**
- `ngl=20`（更多层上 GPU）**比 12 更慢**——层在 GPU/CPU 之间来回搬的开销，
  大于多上几层省下的计算

所以 `config/models.yaml` 里 memory 的默认值写死 **12**，并在注释里说明原因。

> 不适用：这个拐点依赖显卡/模型/上下文长度，换卡要重测。

---

## 5. 编造的最有效解法是**确定性剪枝**，不是让模型"注意点"

困难测试里，「你上次也说过…」这类**无凭据的旧事指涉**出现率：

| 做法 | 出现率 |
|---|---|
| 基线（只靠提示词） | 25% |
| 加人设约束（提示词层） | 21% |
| 扩充标记词表（提示词层） | 21% |
| **按标记把那一小句直接剪掉（程序层）** | **0 / 24** |

关键：**模型做不到"记得清就说得清、记不清就别说"**，
但程序可以在**输出之后**把越界的那一句剪掉，剩下的保留。

对照组（B 组「我以前住哪」这类**有记忆依据**的）保持 3/3 正确，说明没误杀。

> 不适用：剪枝依赖标记词表。全新的说法（词表里没有）剪不到。

## 6. 「回声」检测：bigram 重叠的停用词表**不能太狠**

检测"回复是不是在复读用户"用 bigram 重叠率。第一版把
`说/想/什/么/都` 这类高频字也当停用词过滤掉，把**内容 bigram 也吃掉了**：

- 过狠停用词：重叠率 **0.14**（该判回声的判不出来）
- 只滤虚词 + 去标点：重叠率 **0.42**

同一个检测器，参数差一点结论就反过来。**之前所有依赖它的数字都被污染过**。

> 教训：测量工具本身要先验证。落在阈值附近的"结论"，
> 先怀疑仪器。

## 7. SQLite 删除**不清零**，文件里仍能读出明文

`DELETE FROM episodic` 之后 `SELECT COUNT(*)` 是 0，但 `PRAGMA freelist_count`
显示页被标记为空闲而**内容还在原处**。

实测：一个"已清空记忆"的 163 KB 库里，仍能直接读出 **745 段中文明文**
（包括"刚搬到广州"这类句子）。

结论：**"清除记忆"= 逻辑删除，不等于数据消失**。
要把库交给别人/发出去，必须重建成新库（或 `VACUUM` 后确认没有残留）。

## 8. `pathlib.Path("")` 等于 `Path(".")`，`.exists()` 永远为 True

```python
pathlib.Path("").exists()      # True
pathlib.Path(str(None or "")).exists()   # True ← 踩过
```

用来判断"模型文件在不在"时，**"一个都没有"会被判成"有"**，
于是后面所有断言照常执行、全线报错，而看起来像是文件损坏。

正确写法：先判空再判存在。

## 9. YAML 双引号标量会把**字面换行折成空格**

```yaml
key: "第一行
第二行"          # 实际值是 "第一行 第二行"，换行变成一个空格
```

写配置生成器时，如果只转义了双引号没转义换行，**话术会悄悄变味**，
而且不报错。实测当时把
「…糊弄你。\n换个我能帮上的…」写成「…糊弄你。 换个我能帮上的…」。

正确做法：把 `\n` 转义成 `\\n`，并加一个"写出去再读回来必须一字不差"的自检。

## 10. 配置文件缓存的键只认 `st_mtime` 会漏更新

`st_mtime` 是**秒级**（部分文件系统更粗）。**同一时间片内连写两次**，
第二次的 mtime 与第一次相同 → 缓存不失效 → 读到上一次的内容。

症状是"改完配置没生效"，且**单跑一次永远看不到**（我是连跑 5 次回归才暴露）。

改成 `(st_mtime_ns, st_size)` 做键。

## 11. 程序判不了的事，别硬塞给程序

整条链路的分工是**模型提议、程序决定**：

- 记忆抽取：让模型给候选，**程序**按规则过滤
- 编造：**程序**按标记剪枝（第 5 条）
- 判官：程序侧判不动时才叫模型（第 3 条）

而且两边的**误判代价不对称**，所以阈值方向要分开定：

- 记忆：**误杀 = 丢记忆**，代价大 → 宁可漏拦
- 回复补充：**丢错 = 回复短一点**，代价小 → 拿不准就丢

同一个 `strip_claims` 因此有 `fallback=""` 的分支：主回复剪光给安全兜底，
补充句剪光就**返回空**（否则会拼出自相矛盾的句子）。
